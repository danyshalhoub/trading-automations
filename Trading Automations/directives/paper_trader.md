# Directive: Live Paper Trader

## Objective
Run a roster of strategies live against real daily price data on Alpaca **paper** trading only, keep an honest record of how they actually perform, and re-test/refresh that roster whenever Dany chooses to rerun the tournament — there is no passive weekly automation. If a week goes by without a rerun, the roster simply stays as-is; that's a deliberate choice ("keep the same 4"), not a failure state.

## Tools
- Script: `paper_trader/strategies_lib.py` — shared indicator engine (RSI, MACD, Bollinger, MA crosses, gaps, volume, seasonality, relative strength, etc.). Every strategy is a "spec" — `{name, indicator_type, params, hold_days}` — evaluated through this same fixed, vetted code, whether backtesting or trading live. `indicator_type` must be one of the registered types; `params`/`hold_days` are clamped to hard-coded safe bounds (`clamp_params`, `clamp_hold_days`) before ever being backtested or traded, regardless of where the spec came from.
- Script: `paper_trader/active_strategies.json` — the current live roster (4 strategy specs). `trader.py` reads this every day; `weekly_tournament.py` rewrites it whenever it's run.
- Skill: `.claude/skills/stock-thesis-generator/` — run this in a Claude Code session to generate 20 new candidate strategy *parameterizations* as structured JSON (indicator_type + params + a plain-English thesis) — never code — written to `paper_trader/weekly_candidates.json`. Replaces the old `thesis_generator.py` script, which called the Anthropic API directly (paid, and required a passive GitHub Actions secret Dany never set up); this does the same reasoning for free, on demand, in-session.
- Script: `paper_trader/weekly_tournament.py` — the re-tournament, run manually whenever Dany decides to: downloads price data through *today* (a rolling window, not a fixed range — this is what makes "rerun" actually mean something), loads `weekly_candidates.json` if present (produced by the skill above; absent file just means "re-test the 4 incumbents only, no new candidates"), backtests incumbents + any candidates together, applies the train/test cheat-check (train ≤ 2021-12-31, test > 2021-12-31 through today), ranks cheat-check survivors by test-half P&L, and takes the top 4. If fewer than 4 survive, keeps incumbents (in their prior order) in the remaining slots rather than shrinking the roster. Writes the new roster to `active_strategies.json`, appends full results to `thesis_history.jsonl`, writes `weekly_tournament_report.md`, and deletes `weekly_candidates.json` so it can't be silently reused next time.
- Script: `paper_trader/trader.py` — scans `strategies_lib.ALL_TICKERS` for whatever's in `active_strategies.json`, enters/exits positions on each strategy's `hold_days` timer, appends every closed trade to `paper_trader/trade_log.csv`.
- Script: `paper_trader/performance_report.py` — reads `trade_log.csv`, writes `paper_trader/performance_report.md` (win rate, total trades, per-trade % gain, per-strategy breakdown), and emails a weekly digest. The report and email both show two sections: "This Week" (trades with `exit_date` in the last 7 days) and "All-Time" (cumulative since inception) — don't conflate the two when reading the Total P&L figure (fixed 2026-07-26 after the cumulative total was mistakenly sent as if it were the week's P&L).
- Script: `paper_trader/notify_failure.py` — emails an alert if any workflow step fails (auth expired, rate-limited, unhandled exception). Shared by both workflows via the `WORKFLOW_NAME` env var. Only runs on failure.
- Workflow: `.github/workflows/daily_trader.yml` — runs `trader.py` + `performance_report.py` after US market close on weekdays, commits `positions.json`, `trade_log.csv`, and `performance_report.md` back to the repo.
- Workflow: `.github/workflows/weekly_tournament.yml` — **manual-only** (`workflow_dispatch`, no cron schedule). Trigger it from the GitHub Actions tab (or just run `weekly_tournament.py` locally with Claude Code) whenever the tournament should rerun; auto-commits the new `active_strategies.json` + `thesis_history.jsonl` + report straight to `main` when it runs. No human review step on the commit by design (paper trading only, no real money at risk) — see Safety Rules.

## Expected Outputs
- `positions.json` — currently open positions.
- `trade_log.csv` — one row per closed trade (ticker, strategy, entry/exit date, entry/exit price, shares, % gain, $ P&L). This is the source of truth for live performance — never delete rows from it.
- `performance_report.md` — regenerated every run; summary stats + full trade table.
- `active_strategies.json` — the current live roster of exactly 4 strategy specs; rewritten every Friday.
- `thesis_history.jsonl` — one JSON line per week: every candidate evaluated that week (new + incumbent), its full backtest stats, cheat-check verdict, and which 4 made the next roster. Append-only audit trail — never delete rows from it.
- `weekly_tournament_report.md` — human-readable summary of the latest weekly run.
- A weekly email (Fridays, via `performance_report.py` which still runs on the daily schedule) to `GMAIL_ADDRESS` summarizing win rate, trade count, and P&L. Skipped automatically if no trades have closed yet. Unrelated to the (now manual-only) tournament rerun — this keeps running regardless of whether the roster was refreshed that week.
- A failure-alert email to `GMAIL_ADDRESS` any day either workflow errors out (no silent failures — if you don't hear from it and don't get an alert, check the Actions tab manually).

## Key Settings
- `active_strategies.json` — the live roster; each spec's `hold_days` and `params` are the per-strategy exit timer / thresholds.
- `POSITION_SIZE` (top of `trader.py` and `strategies_lib.py`) — flat dollar amount per trade.
- `strategies_lib.PARAM_BOUNDS` / `HOLD_DAYS_BOUNDS` — the hard safety clamps every strategy spec passes through before it can be backtested or traded, regardless of source.
- `weekly_tournament.TRAIN_CUTOFF` / `MIN_TRADES_TO_SURVIVE` / `ROSTER_SIZE` — cheat-check split date, minimum trade count to be statistically meaningful, and roster size (currently 4).
- Required secrets (GitHub Actions repo secrets, or local `.env` — see `.env.example`): `ALPACA_API_KEY`, `ALPACA_SECRET_KEY`, `GMAIL_ADDRESS`, `GMAIL_APP_PASSWORD` (a Gmail *app password*, not the real password). No Anthropic API key is needed anywhere in this pipeline anymore.

## How the Roster Changes Over Time
This went through three phases: (1) fully manual — re-run tournament scripts by hand, eyeball `performance_report.md`, hand-edit `trader.py`'s strategy list; (2) fully passive — `weekly_tournament.yml` auto-ran every Friday and called the Anthropic API directly via `thesis_generator.py`; (3, current) **manual, by design** — Dany never set up billing for the passive API call, and decided passive automation wasn't the right model anyway. Now:
  - To rerun the tournament: run the `stock-thesis-generator` skill in a Claude Code session (writes `weekly_candidates.json`), then run `weekly_tournament.py`. Or trigger `weekly_tournament.yml` manually from the GitHub Actions tab (with `weekly_candidates.json` pre-committed, or without it to just re-test incumbents).
  - To skip a week: do nothing. `active_strategies.json` isn't touched by anything except `weekly_tournament.py`, so the same 4 strategies keep trading via `trader.py` until the next manual rerun. This is a valid, intentional choice, not a degraded state.
  - A candidate's `indicator_type` + tunable params always come from the fixed registry in `strategies_lib.py`; nothing (Claude in a session, or a hand-authored spec) ever writes or influences execution code, so a bad or adversarial candidate can't produce out-of-range behavior — every param is re-clamped before use regardless of source. To retire an indicator type entirely (not just let it lose a given tournament), remove it from `strategies_lib.DIRECTIONS`/`PARAM_BOUNDS` — that requires a human edit and a normal commit, same as any other code change.

## Safety Rules
- `paper=True` must never be removed from `make_client()` in `trader.py`.
- Never hardcode `ALPACA_API_KEY`/`ALPACA_SECRET_KEY`/`GMAIL_APP_PASSWORD` — always read from environment/secrets.
- `trade_log.csv` and `thesis_history.jsonl` are append-only records — trading logic should only ever add rows, never rewrite or delete history.
- Candidate strategies — whether hand-authored or proposed by Claude in a session via the `stock-thesis-generator` skill — never come with executable code, only structured `{indicator_type, params, hold_days, thesis}` that `strategies_lib.py` clamps to fixed bounds and evaluates through hand-written, human-reviewed indicator formulas. This is why auto-commit to `main` is acceptable when `weekly_tournament.yml` is triggered, despite no human review step on that commit: the blast radius of a bad proposal is bounded by the clamps and the fixed indicator set, and it's paper money regardless.
- If you ever add real-money trading, revisit the "no human review" decision above — it was made specifically because this is paper-only.
